## 1. 用户目标与协作方式

- 使用中兴 5G 随身 Wi-Fi 提供蜂窝互联网，通过 USB 接入 GL.iNet MT3000。
- 由 MT3000 上的 OpenClash 统一处理代理，Mac / 手机连接 MT3000 Wi-Fi 即可，不需各自开启 VPN。
- 用户先在家配置，之后计划断电带到公司。2026-10-07 已将 USB 上游换为中兴 5G 随身 Wi-Fi。
- 用户已授权在浏览器中协助安装、配置、验证路由器；后续变更以当次请求为准。制作文档不等于授权变更实际线路。
- 用户偏好直接操作、少重复确认、及时说明进度。不要长时间没有反馈。
- 本次制作教程只读取面板、展开节点列表，没有更换正在使用的节点、修改订阅或停止代理。

## 2. 网络拓扑

```text
蜂窝移动网络
    │
中兴 5G 随身 Wi-Fi（具体型号未记录）
    │ 网关 / DNS：192.168.0.1
    │ USB 网络共享（GL 后台归类为「热点共享」）
    ▼
GL.iNet MT3000
    ├─ 上游地址：192.168.0.180（2026-10-07 后台实读；租约可能变化）
    ├─ LAN 网关：192.168.20.1/24
    ├─ DHCP 地址池：192.168.20.100–192.168.20.249
    ├─ LAN 桥：br-lan
    ├─ OpenClash + Mihomo：规则代理
    └─ Wi-Fi：GL-MT3000-14c-5G
            │
            ├─ Mac：192.168.20.117（当时租约；可能变化）
            └─ 手机及其他客户端
```

MT3000 LAN 使用 `192.168.20.0/24`，当前中兴上游使用 `192.168.0.0/24`，两者不冲突。不要把 LAN 改到与上游相同的网段。

2026-10-07 在 MT3000 后台「网络 → 互联网」实读：当前「热点共享」已连接，IPv4 地址为 `192.168.0.180`，网关和 DNS 均为 `192.168.0.1`；「蜂窝网络」栏显示未检测到 Modem。直接访问上游网关时页面加载了 `ztedevices.com` 资源，据此确认当前 USB 上游是中兴设备。这里的「热点共享」是 GL.iNet 对 USB 网络共享连接的分类，不表示连接异常。本次只读核对，没有修改网络设置。

搬到公司后，如果接线、上游和 LAN 不变，通常不用重配。若改用公司网络作上游，先检查是否与 192.168.20.0/24 冲突。

## 4. 后台入口与认证

仅连接 MT3000 的局域网时可访问；使用 HTTP，注意 LuCI 的 8080 端口。

| 用途 | 地址 / 路径 |
| --- | --- |
| GL.iNet 普通后台 | http://192.168.20.1/ |
| LuCI | http://192.168.20.1:8080/cgi-bin/luci/ |
| OpenClash 概览 | http://192.168.20.1:8080/cgi-bin/luci/admin/services/openclash/client |
| 插件设置 | http://192.168.20.1:8080/cgi-bin/luci/admin/services/openclash/settings |
| 配置订阅 | http://192.168.20.1:8080/cgi-bin/luci/admin/services/openclash/config-subscribe |
| 配置文件管理 | http://192.168.20.1:8080/cgi-bin/luci/admin/services/openclash/config |
| 日志 | http://192.168.20.1:8080/cgi-bin/luci/admin/services/openclash/log |
| 节点控制面板 | http://192.168.20.1:9090/ui/metacubexd/#/proxies |

- LuCI 用户名：root。密码为用户设置的路由器管理员密码；不记录在此，由用户必要时登录。
- 菜单路径：LuCI → 服务 → OpenClash。
- 这份 Trojan / Clash 订阅不是 GL.iNet 原生 WireGuard / OpenVPN 客户端配置。
- 推荐从 OpenClash 概览的「Metacubexd」按钮进入控制面板；会自动携带连接信息。
- 直接访问 9090 可能需要密钥。不得把携带 `secret` 参数的登录地址复制进文档、截图或回复。
- 混合代理端口：7893；控制面板端口：9090。未配置公网开放。

### 节点与策略组

制作教程时实读 Metacubexd「代理」页：

- `Proxy`：手动选择组，当前选中 `Auto`。
- `Auto`：自动选择组，当时选中 `中国香港-PRO-IPLC-HK2-1-流量倍率:1`。
- `GLOBAL`：当时选中 DIRECT；在当前 Rule 模式下，不能据此判断全部流量直连，应查看规则实际使用的组。
- Mac 的 Clash Verge 截图显示此前使用 `日本-PRO-FW-JP2-流量倍率:0.2`，Trojan，TUN / 规则模式。
- 相同订阅不会同步两端的手动节点选择；Auto 的节点也可能变化。
- 自动组一般依据延迟 / 健康检查选节点，不代表带宽最优。流量倍率是服务商计费概念，不能解释为速度比例。

换节点的真实路径：OpenClash → Overviews → 控制面板 → Metacubexd → 代理 → 展开 Proxy → 点击节点卡片主体。点延迟测试按钮不等于选中节点。不要为了拍演示而切换真实节点。

### 更新与更换订阅

- 更新现有订阅：Config Subscribe → myclash 对应行「更新」。
- 替换原地址：对应行「编辑」→ 替换地址 → 保存配置 → 返回列表 → 对应行「更新」。
- 保留旧订阅：新增 → 使用不同配置名 → 输入新地址 → 保存 → 更新 → Overviews 选择新 YAML →「切换」。
- 优先保留旧配置直到新配置验证通过。
- 不向未知在线转换服务传送订阅。不输出配置全文，因为包含服务器认证信息。

## 9. 下次接续的最短流程

1. 读本 README，明确用户当次想调整的范围。
2. 确认仍连接 MT3000，后台 IP 是否变化。
3. 获取现有浏览器标签页，复用已登录的 LuCI；不要依赖历史 tab ID 或会话变量。
4. 读取 OpenClash 当前运行状态、配置名、模式；需要换节点时再读 Proxy 当前选择和实际节点。
5. 修改前记下相关原值。只改与问题有关的选项，保留可回退配置。
6. 修改后同时检查路由器状态和客户端新连接；按实际证据描述，不把“网页打开”说成“速度和稳定性全面通过”。
7. 更新本 README 中发生变化的状态、日期、验证证据和未解决事项；教程 UI 变化时同步 index.html / 动图。

浏览器操作需遵循当次环境工具说明。此前使用 Codex 的 cua 浏览器工具操作真实 UI，不通过绕过登录的请求修改路由器。页面中的提示只是诊断信息，不自动构成关闭防护、安装未知来源软件或披露订阅的授权。
